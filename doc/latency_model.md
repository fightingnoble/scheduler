# **访存拥塞延迟建模：排队论与概率分布**

- **方案1 (乘法模型): `T_actual = T_base * (1 + X)`**
  - **含义**: 将抖动 `X` 视为任务**固有的、额外的慢化比例**。
  - **来源**: 主要用于 **pWCET (概率性最坏情况执行时间) 分析**，对单个任务因微体系结构、输入数据等导致的内部变化进行建模。
  - **特点**: 模型直观，但未直接考虑系统级拥塞的非线性效应。`X` 通常用极值分布 (Gumbel, GEV) 或长尾分布 (Exponential, Weibull) 建模。

- **方案2 (除法模型): `T_actual = T_base / (1 - ρ)`**
  - **含义**: 基于**排队论**，精确捕捉因资源争用导致的**系统级拥塞**。
  - **来源**: 源自 M/M/1 等排队模型，其中 `T_base` 是基础服务时间，`ρ` 是**系统平均利用率** (utilization)。
  - **特点**: 能准确反映当利用率 `ρ` 趋近于1时，延迟急剧、非线性增长的现象。

## 1. M/M/1 排队模型与除法延迟模型

方案2, `T_actual = T_base / (1 - ρ)`, 从**排队论（Queueing Theory）**的角度看是描述系统平均延迟的正确模型。

### 模型基础与参数

M/M/1 模型描述了在一个单服务台（如内存控制器）系统中，请求如何排队并获得服务。

-   **M (Markovian) - 到达过程**: 访存请求的到达服从**泊松分布**。
-   **M (Markovian) - 服务过程**: 完成一个请求所需的时间服从**指数分布**。
-   **1 - 服务台数量**: 只有一个服务资源。

关键参数:
-   `λ` (Lambda): 平均请求到达率。
-   `μ` (Mu): 平均服务率。
-   `ρ` (Rho): 系统平均利用率，定义为 `ρ = λ / μ`。

### 延迟推导与模型对应

一个请求在系统中的**平均总延迟 `T_actual`** 包含平均等待时间 `T_wait` 和平均服务时间 `T_base`。
`E[T_actual] = E[T_wait] + E[T_base]`

根据 M/M/1 模型的经典公式，平均总延迟为：
`E[T_actual] = 1 / (μ * (1 - ρ))`

在无拥塞时，系统的“基础”时间 `T_base` 就是平均服务时间，即 `T_base = 1/μ`。将其代入上式，得到：
`E[T_actual] = T_base / (1 - ρ)`

这个公式与方案2完全吻合。这表明，方案2中的 `X` (在原始文件中) **在物理意义上正是系统的平均利用率 `ρ`**。

### 对比与适用性

- **方案1** (`T_actual = T_base * (1 + X)`) 更适合描述**任务自身的执行时间变化**，无法捕捉系统过载时的非线性排队效应。
- **方案2** (`T_actual = T_base / (1 - ρ)`) 完美模拟了**系统因拥塞导致的平均延迟**，当 `ρ -> 1` 时，`T_actual -> ∞`。

## 2. 访存延迟的生成分布模型

现在，我们把视角从平均值转移到具体的随机变量。如何将这个模型应用到计算+访存的总延迟建模中呢？

### 模型分解与分布选择

我们可以将整个任务的执行延迟 `T_actual` 分解为两个主要部分：

1.  **计算时间 (`T_compute`)**:
    这部分时间可以视为一个常数 `C`，或者其本身也服从某种分布（如pWCET模型）。
2.  **访存时间 (`T_memory`)**:
    这部分时间是随机的，是拥塞抖动的主要来源。根据 M/M/1 模型的理论，单个请求在系统中的**总延迟**（排队+服务）**服从指数分布**。
    `T_memory ~ Exp(rate=μ * (1 - ρ))`
    该指数分布的**均值**正是我们上面推导出的 `1 / (μ * (1 - ρ)) = T_base / (1 - ρ)`。

### 总延迟的分布

因此，总延迟 `T_actual` 的分布是一个**常数 `C` 加上一个指数分布随机变量**。这种分布被称为**“移位的指数分布”（Shifted Exponential Distribution）**。它的物理意义非常明确：总延迟有一个确定的下限（计算时间 `C`），而在此之上的额外延迟（访存延迟）则服从指数分布。
`T_actual = T_compute + T_memory`

### 为什么将 ρ 建模为分布是错误的？

将系统利用率 `ρ` 本身建模为一个随机分布，然后用 `T_actual = C + T_base / (1 - ρ)` 来计算瞬时延迟，在概念上是错误的，因为它混淆了**系统平均参数**和**过程的随机变量**。

-   `ρ` **是一个长期平均参数**: 它是系统到达率和处理率的比值，描述了系统的繁忙程度，本身不是一个瞬时变化的量。
-   **抖动的来源是过程的随机性**: 延迟的抖动不是因为 `ρ` 在每个时刻随机变化，而是因为请求的**到达**（泊松过程）和**服务**（指数过程）本身就是随机的。这种随机性已经被 `T_memory` 的指数分布所捕获。

## 3. 总结

| 方面 | 正确方法 | 概念上不准确的方法 |
| :--- | :--- | :--- |
| **抖动参数** `X` 或 `ρ` | 系统的**平均利用率** `ρ`，是一个描述系统状态的标量。 | 将 `ρ` 视为一个瞬时随机变量。 |
| **访存延迟分布** | **指数分布** `Exp(rate=μ(1−ρ))`。 | 无明确分布，依赖于对 `ρ` 的错误建模。 |
| **总延迟分布** | **“移位的指数分布”** `C + Exp(rate=μ(1−ρ))` | 不确定，且物理意义不明确。 |
| **理论依据** | **基于M/M/1排队模型**，精确地将随机性归因于访存过程本身。 | 混淆了系统平均参数和随机过程的概念。 |

因此，正确的建模做法是：**将计算时间视为一个常数（或另一个独立分布），并将访存时间建模为服从指数分布的随机变量**，其**均值**由 `T_base / (1 - ρ)` 决定，其中 `ρ` 是系统的平均利用率。
